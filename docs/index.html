入门 / Overview

插件在 GameSupport 中扮演什么角色

GameSupport 是 Windows 上的游戏桌面增强工具。全局快捷键、插件和本地 HTTP API 都汇入同一个 Event Bus；触发规则决定某个事件发生时播放什么音效或动画。

插件可以提供菜单和工具页面，也可以作为事件源。下图说明事件插件的工作方式。它不直接操作播放器，也不需要知道用户配置了哪些音效。你只需要在检测到事情发生时，发送一条格式正确的 JSON 事件。

你负责 插件 EXE 检测逻辑 + JSONL
GS-IPC
GameSupport Event Bus 校验、授权、去重与调度
匹配
主程序 触发规则 事件 ID → 音效 / 动画
执行
原生模块 音效 / 动画 用户配置的输出

插件可以做什么

  • 观察屏幕或窗口画面，识别游戏状态。
  • 监听游戏日志、配置文件或本地数据变化。
  • 连接本地设备、服务或网络接口，把状态转成事件。
  • 运行定时器、计数器或你自己的状态机。

插件不做什么

  • 不播放音效，不渲染动画。
  • 不注册或拦截用户的全局快捷键。
  • 不决定冷却、随机动作或触发次数。
  • 不直接接触播放器或用户素材。
阅读约定

Host 指 GameSupport 主程序；Plugin 指你的插件进程。消息均以 UTF-8 编码，每条 JSON 以 LF 结尾。示例使用 PowerShell，路径均相对于插件包根目录。

JavaScript UI / SDK 1.1

运行动画编辑器示例

node sdk/examples/animation-editor/build.mjs

在插件中心安装 build/animation-editor-plugin，点击“打开工具”或侧栏“动画编辑器”。调整光环、粒子、颜色和速度，预览/拖动帧，保存工程；导出后前往动画库，在触发中心添加规则关联导出的动画。模板是简单效果编辑器，不包含视频剪辑或完整关键帧系统。

}

示例 build.mjs 自动生成真实哈希。一个插件支持 1–8 页，页面 ID 唯一，格式为小写字母开头、字母/数字/下划线/短横线，最长 40 字符；标题最长 40 字符。html、script 必需，style 可选，各文件上限 512 KiB，均须在完整性清单中。HTML 写 body 内的内容，JavaScript 写独立 script 文件，事件用 addEventListener 或元素属性绑定；不要在 HTML 写 script 或 onclick。CSS 写独立 style 文件，可用 Canvas、内嵌 data 图片和浏览器 File API。

事件插件保持 type: event_provider 与现有 native runtime，仅新增 ui 字段即可。现有插件包不需要修改。纯界面插件 events 为空，不发送 GS-IPC 事件，也不运行进程；自动启动设置忽略。

JavaScript UI / SDK 1.1

页面 API 1.0

主程序提供 window.GameSupport，GameSupport.apiVersion 为 1.0。脚本运行时即可调用，返回 Promise；失败 reject Error，页面应显示可读错误。

const info = await GameSupport.call('plugin.info');
const project = await GameSupport.call('storage.get');
await GameSupport.call('storage.set', { value: { title: '我的工程', layers: [] } });
const assets = await GameSupport.call('assets.list');
方法参数结果
plugin.info无本插件 id、name、version、api_version
storage.get无本插件保存的 JSON，没有工程时为 null
storage.set{value: JSON}{saved: true}，整体覆盖本插件工程
assets.list无素材 id、name、asset_type、width、height、duration，不含磁盘路径
effects.save下述动画参数导入动画的公开素材信息

工程总计最多 1 MiB，保存到本插件独立 SQLite 记录，同一插件的多个页面共享；与运行配置分开，升级保留。卸载暂时保留工程，同 ID 重装可以读取。页面切换会销毁页面，未保存的内存编辑不会自动保留。不要依赖 localStorage（页面为独立不透明来源）。

导出 GIF

const bytes = canvas.getContext('2d').getImageData(0, 0, width, height).data;
let raw = '';
for (let i = 0; i < bytes.length; i += 8192)
  raw += String.fromCharCode(...bytes.subarray(i, i + 8192));
const asset = await GameSupport.call('effects.save', {
  name: '我的动画', width, height, fps: 24,
  frames: [btoa(raw)] // 每帧为按行排列的 RGBA8 原始数据的 base64
});

名称 1–80 字；尺寸每边 1–256；FPS 1–60；帧数 1–60；所有 base64 帧字符串合计最多 8 MiB，每帧解码长度严格为 width × height × 4。Host 编码循环 GIF，使用普通素材导入校验，返回素材 ID。GIF 使用有限调色板与二值透明度，不能完整保留 RGBA 的半透明渐变；与库内已有文件哈希相同会提示已经导入。插件不能指定输出磁盘路径。导出不会自动创建/触发规则或覆盖已有素材。

JavaScript UI / SDK 1.1

页面边界与更新

页面放在独立 sandbox iframe，只允许脚本，不允许同源访问、弹窗、下载或顶层导航；通过每次打开生成的通道标识与父窗口通信。Host 检查消息来源和固定接口白名单，插件 ID/页面 ID/版本由 Host 绑定，不能通过参数切换到其他插件。页面禁止外网连接、CDN、任意本地文件读取、任意主程序命令和原生进程启动。不支持在此接口里调用 Native 插件自定义命令。

页面代码通过本地 data 文档加载，配有独立 CSP；主窗口不执行插件 HTML/JavaScript。加载前重新检查包与哈希；版本变化/卸载后旧页面请求被拒绝。最多 4 个同时在途请求，请求超时 60 秒；请避免高频轮询和无限循环。浏览器隔离不代表 CPU/内存配额；不要安装不受信任插件。Native 插件仍使用操作系统进程权限，不受 iframe 限制。

更新时提高版本、重新构建哈希并在插件中心更新；重新打开页面加载新代码。将来扩展 API 应保持旧接口兼容，不要直接调用 Tauri 内部接口。

入门 / Quick start

10 分钟跑通模板

先用官方模板确认安装、授权、事件和触发规则整条链路。跑通之后，再把模板里的示例逻辑换成你自己的检测代码。

先确认环境

构建机需要 Windows x64、Node.js 22+ 和 Go。Go 只用于编译最小的 EXE 启动器。最终用户不需要安装 Node 或 Go，运行时会随插件包分发。

  1. 获取模板

    模板仓库包含 plugin.cjs、launcher.go 和 build.mjs，没有 npm 依赖。

    git clone https://github.com/shuo-huge/gamesupport-javascript-plugin.git
cd gamesupport-javascript-plugin

  2. 构建插件包

    构建脚本会编译启动器、复制 Node 运行时、计算 SHA-256 并生成 manifest.json。终端最后一行会打印可安装目录。

    node build.mjs

    输出通常是 build/javascript-example。以脚本实际打印的路径为准。

  3. 安装本地插件

    打开 GameSupport，进入插件中心，点击安装本地插件，选择包含 manifest.json 的构建目录。不要选择它的上级目录。

  4. 直接启动事件插件

    声明能力在安装时自动启用，无需勾选权限。点击启动，等待状态变成运行中。

  5. 创建一条触发规则

    进入触发中心新建规则，事件标识填写 example.pulse，加入你自己的音效或动画并保存。也可以直接从插件卡片点击添加到触发中心 · 示例脉冲。

  6. 请求测试事件

    回到插件配置页，点击请求测试事件。模板会收到 configure 命令并立即发送一条 example.pulse。你应听到音效或看到动画，插件日志也会出现记录。

不需要开启本地 HTTP API

JavaScript 模板通过 stdin/stdout 直接连接主程序。测试事件也不会定时自动发送，只有你点击按钮或满足你自己的触发条件时才发送。

如果链路中断，先看故障排查。最常见的原因是构建目录选错、manifest 没有声明 events.emit、规则中的事件 ID 拼写不一致，或修改源码后没有重新构建。

入门 / Concepts

先记住这六件事

插件系统的规则不多，但每一条都直接影响插件能否启动、能否收到事件，以及更新后如何保留配置和工程。

manifest 是契约

插件 ID、版本、事件、权限和文件哈希都写在 manifest 里。Host 在每次启动前重新校验。

JSONL 是唯一输出

stdout 每一行必须是一条完整的 GS-IPC JSON。普通日志一律写 stderr。

每个插件独立进程

崩溃、协议错误或 JSON 解析失败只影响该插件，主程序和其他插件继续运行。

Event ID 是公开 API

用户规则绑定事件 ID。发布后不要重命名或删除，新增事件比改旧 ID 安全。

声明能力自动启用

安装、更新与启动时自动启用 manifest 声明的能力，不显示权限勾选；未声明事件仍会被拒绝。

JavaScript 不是沙箱

模板用 EXE 启动 Node。权限声明不会限制 Node 的 Windows 文件、网络或进程能力。

一次事件从插件到扬声器

以模板为例，完整链路如下：

  1. 用户在插件配置页点击请求测试事件，Host 发送 configure 命令。
  2. plugin.cjs 调用 emitPulse()，向 stdout 写入一条 event 消息。
  3. Host 校验插件已授权 events.emit，并且事件已在 manifest 中声明。
  4. Host 为事件补充可信来源和时间戳，放进统一的 Event Bus。
  5. 触发规则匹配事件 ID，调度音效或动画。
  6. 插件日志、事件记录和实际播放各自独立记录；已调度表示进入队列，不等于测得播放成功。
规范 / Structure

一个插件包里有什么

源码目录和安装目录是两回事。源码包含启动器的 Go 文件；安装目录只保留运行所需的文件、清单和哈希。

源码目录

my-plugin/
├─ plugin.cjs        # 你的插件逻辑
├─ launcher.go       # EXE 启动器源码
├─ build.mjs         # 构建、复制运行时、生成哈希
└─ README.md         # 使用说明与权限披露

安装目录

build/demo-timer/
├─ manifest.json     # 由构建脚本生成
├─ plugin.cjs
├─ NODE-LICENSE.txt
└─ bin/
   ├─ launcher.exe
   └─ node.exe
文件作用注意
plugin.cjs插件的全部运行逻辑，由 Node 执行。stdout 只写 GS-IPC JSON；日志用 console.error。
launcher.exeHost 实际启动的入口，把 stdin/stdout/stderr 原样转给 node.exe。由 launcher.go 编译，Native 事件运行时只接受 EXE 入口，且不传命令行参数。
node.exe随包分发的 Node 运行时。体积较大；必须保留版权与第三方声明。
manifest.json插件身份、事件、权限与完整性清单。不要手改安装目录中的副本；重新构建再更新。
NODE-LICENSE.txtNode 运行时的许可文本。分发运行时必须附带。
不能只安装一个 .js 文件

Native 事件运行时的入口必须是包内的 .exe。模板用一个小型启动器承载 Node，这是为了适配现有 Native 插件进程模型，不代表 JavaScript 运行在沙箱里。

如果引入 npm 依赖

模板刻意不使用 npm 依赖。你可以引入第三方包，但必须把运行时需要的文件一起放进安装目录，并全部纳入 files 哈希。最终用户不会执行 npm install。依赖过多时也可能触达 512 个目录项或 512 MiB 的包体上限，优先选择无依赖或可打包成单文件的方案。

规范 / Manifest

插件清单参考

manifest.json 描述插件是谁、能发送哪些事件、需要哪些权限，以及包内每个文件的哈希。Host 在安装和每次启动前都会校验它。

让构建脚本生成它

模板中的 build.mjs 会写出 manifest 并计算哈希。手写容易漏文件或写错版本。安装后也不要直接修改用户目录里的副本，Host 会按清单重新校验。

{
  "manifest_version": 1,
  "id": "com.example.demo-timer",
  "name": "Demo Timer",
  "version": "1.0.0",
  "author": "Your Name",
  "description": "按固定间隔发送 demo.timer.tick 事件。",
  "type": "event_provider",
  "runtime": {
    "type": "native",
    "os": ["windows"],
    "arch": ["x86_64"],
    "executable": "bin/launcher.exe",
    "protocol": "gs-ipc/1.0"
  },
  "permissions": ["events.emit"],
  "events": [
    { "id": "demo.timer.tick", "name": "计时器滴答" }
  ],
  "files": {
    "bin/launcher.exe": "由 build.mjs 生成的 64 位十六进制",
    "bin/node.exe": "由 build.mjs 生成的 64 位十六进制",
    "plugin.cjs": "由 build.mjs 生成的 64 位十六进制",
    "NODE-LICENSE.txt": "由 build.mjs 生成的 64 位十六进制"
  }
}
字段约束说明
manifest_version固定 1清单格式版本，当前只支持 1。
id反向域名，≥3 段，小写全局唯一。配置、授权和更新都以它为键，发布后不要改。
name1–100 字符插件中心显示的名字。
versionSemVer1.0.0 或 1.1.0-beta.1。更新必须严格高于已安装版本。
author非空字符串个人或团队名称。
description≤2000 字符说明插件做什么、读取什么、发送哪些事件。
typeevent_provider 或 ui事件提供者或纯界面插件；均可声明 ui.pages。
runtime对象事件插件使用 native/os/arch/executable/protocol；纯界面插件使用 {"type":"web"}，并声明 ui.pages。
permissions枚举数组只能声明 Host 支持的六种权限，详见权限模型。
events最多 128 项每项包含 id 与 name。未声明的事件发送会被拒绝。
ui.pages1–8 个页面id、title、html、script 必填，style 可选；文件须在哈希清单中。详见页面清单。
files1–256 项包内除 manifest 外每个文件到小写 SHA-256 的映射。安装和启动前都会校验。

Schema 不允许未定义字段（additionalProperties: false）。多写一个字段会导致清单校验失败。

插件 ID 规则

ID 使用反向域名格式，至少三段。它同时是插件目录、配置记录和授权记录的主键。

可以

  • com.example.demo-timer
  • com.yourstudio.boss-alert
  • io.team.game.events

不可以

  • demo-timer：只有一段。
  • com.Example.Demo：包含大写字母。
  • com.example..timer：空段。

版本规则

  • 使用语义化版本：主版本.次版本.修订号。
  • 更新包必须与已安装插件同 ID，且版本严格更高；降级会被拒绝。
  • plugin.cjs 中 hello.version 必须与 manifest 的 version 完全一致，否则握手失败。
  • 每次向用户分发新的代码或资源，都要提升版本并重新构建，让哈希与清单一起更新。

事件声明

事件 ID 使用小写字母、数字、下划线和点号，例如 game.kill、demo.timer.tick、screen.boss.enter。名字是展示给用户的说明。

  • 事件 ID 是对外 API。用户规则直接绑定它。发布后不要重命名或删除；需要变化时新增一个 ID，并保留旧事件一段时间。
  • 声明了但暂时没有发送是允许的。发送未声明的事件会被 Host 拒绝。
  • 事件发送还必须获得 events.emit 授权。

完整性与包体限制

files 必须包含安装目录中除 manifest.json 以外的所有文件，包括 EXE、DLL、Node 运行时和许可文本。Host 会重新计算哈希，不匹配就拒绝启动。

限制数值
manifest 文件大小≤128 KiB
安装包总大小≤512 MiB
包内目录项≤512
files 条目1–256
路径必须是相对路径；禁止绝对路径、..、NTFS 数据流、符号链接和目录联接。

哈希值必须是小写十六进制 SHA-256。修改任意文件后，旧 manifest 立即失效，必须重新构建。

规范 / Protocol

GS-IPC / 1.0 协议

插件通过标准输入输出与 Host 通信。stdin 接收命令，stdout 发送消息，stderr 写日志。没有 HTTP、没有端口、没有额外 SDK。

通道方向用途
stdinHost → Plugin初始化、启动、心跳、配置和停止命令。
stdoutPlugin → Host只允许 GS-IPC JSON。每行一条，以 LF 结尾。
stderrPlugin → Host 日志普通日志、错误和调试信息。不会进入协议解析。
stdout 是协议通道，不是日志窗口

console.log()、调试输出、进度条或任何非 JSON 文本都会破坏协议。普通日志请使用 console.error()。stdout 也不能输出图像或二进制。

连接限制

项目限制
编码与分帧UTF-8；每条 JSON 以 LF 结束；每行最多 65,536 字节（含 LF）。
消息速率每个插件每秒最多 100 条 Plugin → Host 消息。
事件 data≤32 KiB。
Host 收件队列128 条。
统一事件队列256 条。
initialize 配置≤32 KiB 的 JSON 对象。
握手阶段超时每个阶段 5 秒。
心跳每 5 秒一次；15 秒没有 pong 会被终止。
停止等待2 秒；超时强制终止并回收进程树。

队列满、非法消息、JSON 解析错误或握手错误都会中止该插件并写入异常日志。其他插件和主程序不受影响。

事件消息

事件消息只有两个业务字段：event 是 manifest 中声明的事件 ID，data 是附带的 JSON 对象。Host 会在下游补充可信的 source 与 timestamp。

  • 不要在 data 中伪造来源或时间戳；Host 不信任插件提供的来源身份。
  • data 建议始终使用 JSON 对象，保持结构稳定，方便用户规则和后续版本兼容。
  • 事件 data 上限 32 KiB。高频事件应先在自己的逻辑里去重或合并。
  • 发送频率受每秒 100 条消息限制。队列满时 Host 会中止插件。

心跳与阻塞

Host 每 5 秒发送 ping。插件必须在 15 秒内回复对应的 pong。同步死循环、长时间阻塞的 CPU 计算、同步文件或网络调用都会让 Node 事件循环停住，最终被 Host 终止。

长任务要拆分

屏幕处理、图像解码或大文件读取应使用异步 API，或分成小块在事件循环中执行。不要在 line 回调里做会持续数秒的同步计算。

停止与异常

收到 stop 后，插件应停止定时器、关闭连接、释放句柄，发送 status: stopped，然后以退出码 0 结束。Host 等待 2 秒；超时会强制终止，并通过 Windows Job Object 回收子进程树。

进程意外退出、协议错误和 JSON 解析错误都只影响当前插件。Host 不信任插件提供的错误码，也不会把错误码当作命令执行。

声明能力与页面接口

安装、更新、启动 Native 插件时自动启用清单声明能力，不再提供权限勾选。事件必须在 events 中声明，并声明 events.emit。能力记录不是 Windows 权限沙箱。

六种 Native 声明能力为 screen.capture、events.emit、filesystem.read、filesystem.write、network.client、process.launch。界面插件使用固定 GameSupport.call 接口，不能通过权限声明解锁任意文件、网络或系统命令。

纯界面插件使用 permissions: []、events: []。具体边界见页面边界。

生命周期与更新

事件插件：已安装 → starting → running → stopping → stopped；异常进入 error。插件配置与可选自动启动保存在 SQLite。更新必须同 ID、更高版本，先停止旧进程；暂存校验后替换目录，常规失败回滚，保留配置和自动启动选择，并自动启用新清单声明能力。尚无断电级事务恢复日志。

界面插件无需启动，安装后显示侧栏菜单。切换页面销毁当前 iframe，未保存编辑会丢失；storage.set 保存的工程独立持久化，更新保留。更新后重新打开页面。卸载移除菜单和页面；工程暂时保留，同 ID 重装可读取。

卸载不删除已导入的音效、动画与触发规则。配置会备份到 profiles；重装恢复配置并自动启用声明能力。

教程：做一个计时器插件

这个插件每隔一段时间发送 demo.timer.tick，间隔由用户在插件配置中填写。它覆盖了配置读取、定时器、心跳、测试命令和优雅停止。

完成后你会得到
  • 一个可安装的 build/demo-timer 目录。
  • 事件 demo.timer.tick，能绑定任意音效或动画。
  • 可配置的间隔 {"interval_ms":5000}。
  • 一条可以重复使用的构建、安装、更新流程。

  1. 复制模板并确定身份

    复制模板目录，为插件选择一个不会被别人使用的反向域名 ID。本教程使用 com.example.demo-timer，发布前请换成你自己的域名。

    需要保持同步的三处信息：

    位置需要修改
    build.mjs输出目录、id、name、version、events 和权限。
    plugin.cjshello 中的 plugin_id 与 version。

  2. 写入插件逻辑

    用下面的内容替换 plugin.cjs。代码只使用 Node 内置模块，不需要 npm 安装。

    // stdout 只允许 GS-IPC JSON。日志一律走 stderr。
const readline = require('node:readline');

const send = (message) => process.stdout.write(`${JSON.stringify(message)}\n`);

let initialized = false;
let running = false;
let canEmit = false;
let timer = null;
let intervalMs = 60_000;

function stopTimer() {
  if (timer !== null) {
    clearInterval(timer);
    timer = null;
  }
}

function emitTick() {
  if (!running || !canEmit) return;
  send({
    type: 'event',
    event: 'demo.timer.tick',
    data: { interval_ms: intervalMs, at: Date.now() },
  });
}

function startTimer() {
  stopTimer();
  timer = setInterval(emitTick, intervalMs);
}

send({
  type: 'hello',
  plugin_id: 'com.example.demo-timer',
  version: '1.0.0',
  protocol: 'gs-ipc/1.0',
});

const rl = readline.createInterface({ input: process.stdin, crlfDelay: Infinity });

rl.on('line', (line) => {
  let message;
  try {
    message = JSON.parse(line);
  } catch (error) {
    console.error(`Invalid JSON: ${error.message}`);
    return;
  }

  try {
    if (message.type === 'initialize') {
      if (initialized || message.protocol !== 'gs-ipc/1.0') {
        throw new Error('Invalid initialize');
      }
      initialized = true;
      canEmit = Array.isArray(message.permissions) && message.permissions.includes('events.emit');

      const requested = Number(message.config?.interval_ms);
      if (Number.isFinite(requested) && requested >= 1_000 && requested <= 3_600_000) {
        intervalMs = requested;
      }
      send({ type: 'ready', request_id: message.request_id });
      return;
    }

    if (message.type !== 'command') return;

    switch (message.command) {
      case 'start':
        if (!initialized) throw new Error('Initialize first');
        if (running) break;
        running = true;
        send({ type: 'status', state: 'running' });
        startTimer();
        break;

      case 'ping':
        send({ type: 'pong', request_id: message.request_id });
        break;

      case 'configure':
        if (message.config?.emit_test === true) emitTick();
        break;

      case 'stop':
        running = false;
        stopTimer();
        process.stdout.write(`${JSON.stringify({ type: 'status', state: 'stopped' })}\n`, () =>
          process.exit(0),
        );
        break;

      default:
        console.error(`Unknown command: ${message.command}`);
    }
  } catch (error) {
    console.error(error.message);
    process.exit(1);
  }
});

rl.on('close', () => {
  stopTimer();
  process.exit(0);
});

  3. 理解关键点

    • 先 hello，再读 stdin。Host 需要立即知道插件身份。hello 的 ID 和版本必须与 manifest 一致。
    • 用 canEmit 检查授权。initialize 传入本次已授权的权限列表。没有 events.emit 就不发送事件。
    • 配置只信任合法范围。间隔限制在 1 秒到 1 小时之间，避免用户填入负数或过小的值导致消息洪泛。
    • 先报告 running，再启动定时器。让 Host 的日志顺序清晰。定时器只在 running 且 canEmit 时发送。
    • 测试命令复用同一个发送函数。configure 中的 emit_test 只触发一次，不改变定时器。
    • 停止时先写 status，再退出。写入回调里调用 process.exit(0)，避免消息还没刷出就被切断。
    • 关闭 stdin 也要清理。Host 进程结束时，close 回调负责清理定时器。

  4. 修改构建脚本的清单信息

    至少修改输出目录、插件身份、事件和权限。下面的片段展示了与模板不同的部分。

    node build.mjs

    构建成功后会生成 build/demo-timer。确认目录里同时存在 manifest.json、plugin.cjs、bin/launcher.exe 和 bin/node.exe。任一项缺失都不要安装。

  6. 安装、启动并填写配置

    在插件中心安装构建目录并启动，声明能力自动启用。打开插件配置。在配置文本框中写入：

    { "interval_ms": 5000 }

    点击保存配置，然后点击启动。配置会通过 initialize 的 config 字段传入插件；保存操作会停止进程，所以必须重新启动才能生效。

  7. 创建触发规则

    在触发中心新建规则，事件标识填写 demo.timer.tick，加入音效或动画并保存。规则的事件 ID 必须与 manifest 和插件发送的 ID 完全一致，包括大小写和点号。

  8. 验证两条路径

    • 测试按钮：点击请求测试事件，Host 发送 configure，插件立即发送一次事件。
    • 定时器：启动后等待 5 秒，插件按 interval_ms 自动发送。

    确认事件记录出现、音效或动画实际执行，并让插件持续运行 30 秒以上，观察心跳是否稳定。

  9. 修改并发布新版本

    把 build.mjs 和 plugin.cjs 中的版本同时改成 1.1.0，重新构建，然后在已安装插件上停止旧版本，点击更新包选择新目录。更新保留配置和自动启动选项，自动启用新清单声明能力；可重新启动测试。

把手工步骤变成清单

每次发布前检查：ID 未变、版本已提升、hello 与 manifest 一致、事件已声明、权限最小、重新构建过、更新后验证配置与能力声明。把这六项写进 README，能避免大多数“更新后不工作”的问题。

实践 / Build

构建、打包与完整性

模板的构建脚本只做六件事：编译启动器、复制 Node 运行时、复制插件逻辑、生成清单、计算哈希、打印安装目录。

构建脚本做了什么

  1. 检查构建机是否为 Windows x64，避免产出无法运行的包。
  2. 用 Go 编译 launcher.go，目标为 Windows amd64，关闭 CGO。
  3. 把当前 node.exe 和它的许可文本复制到 bin/ 与包根目录。
  4. 复制 plugin.cjs。
  5. 写入 manifest 的 ID、版本、运行时、权限和事件。
  6. 对包内四个运行文件计算 SHA-256，写入 files，最后生成 manifest.json。
import fs from 'node:fs';
import path from 'node:path';
import { fileURLToPath } from 'node:url';
import { spawnSync } from 'node:child_process';
import { createHash } from 'node:crypto';

if (process.platform !== 'win32' || process.arch !== 'x64') {
  throw Error('Build with Windows x64 Node.js.');
}

const source = path.dirname(fileURLToPath(import.meta.url));
const output = path.resolve(source, 'build/demo-timer');
fs.mkdirSync(path.join(output, 'bin'), { recursive: true });

const result = spawnSync(
  'go',
  [
    'build',
    '-trimpath',
    '-ldflags=-s -w',
    '-o',
    path.join(output, 'bin/launcher.exe'),
    path.join(source, 'launcher.go'),
  ],
  {
    stdio: 'inherit',
    env: { ...process.env, GOOS: 'windows', GOARCH: 'amd64', CGO_ENABLED: '0' },
  },
);
if (result.error) throw result.error;
if (result.status !== 0) process.exit(result.status ?? 1);

fs.copyFileSync(process.execPath, path.join(output, 'bin/node.exe'));
fs.copyFileSync(
  path.join(path.dirname(process.execPath), 'LICENSE'),
  path.join(output, 'NODE-LICENSE.txt'),
);
fs.copyFileSync(path.join(source, 'plugin.cjs'), path.join(output, 'plugin.cjs'));

  id: 'com.example.demo-timer',
  name: 'Demo Timer',
  version: '1.0.0',
  author: 'Your Name',

启动器

Native 事件运行时只接受 EXE 入口，并且不传命令行参数。启动器的工作是把标准输入输出原样转发给随包的 Node。它不解析协议，也不做业务逻辑。

package main

import (
	"fmt"
	"os"
	"os/exec"
	"path/filepath"
	"syscall"
)

func main() {
	exe, err := os.Executable()
	if err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}
	bin := filepath.Dir(exe)
	child := exec.Command(filepath.Join(bin, "node.exe"), filepath.Join(bin, "..", "plugin.cjs"))
	child.Stdin, child.Stdout, child.Stderr = os.Stdin, os.Stdout, os.Stderr
	child.SysProcAttr = &syscall.SysProcAttr{HideWindow: true}
	if err := child.Run(); err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}
}

启动器用自身 EXE 所在目录解析 node.exe 和 plugin.cjs，因此插件包被安装到任何用户目录都能运行。Node 退出后，启动器以非零状态退出，Host 会把插件标记为错误。

包体会包含完整的 node.exe，不是小体积单文件程序。分发时应保留 Node 的许可文本，并遵守所使用 Node 发行版的第三方声明要求。不要删除 NODE-LICENSE.txt，也不要用来源不明的 node.exe 替换随包运行时。

实践 / Testing

测试与调试

先验证协议，再验证业务。大多数问题不是“事件没发出去”，而是插件根本没有进入 running，或者规则绑定的事件 ID 不一致。

主程序内测试

  • 插件启动后，配置页的请求测试事件按钮才可用。它会发送 configure，模板将其解释为“立即发送一次示例事件”。
  • 插件日志显示状态、协议错误和 stderr 输出。日志只保留状态或错误变化的持久记录，避免每秒状态淹没事件日志。
  • 事件记录中的已调度表示动作进入队列。音频设备错误或动画执行错误会另行写入日志，不等同于播放成功。

直接运行插件逻辑

在构建目录中，可以用一行 initialize 直接喂给 Node，检查 hello、ready 和 JSON 解析是否正常。这个方式绕过 Host 的授权与完整性校验，只用于本地调试。

'{"type":"initialize","request_id":"init","protocol":"gs-ipc/1.0","permissions":["events.emit"],"config":{"interval_ms":5000}}' | node plugin.cjs

stdout 应出现 hello 和 ready。管道关闭后进程退出，不会收到 start。这个检查只能证明握手代码没有语法错误，不能替代主程序集成测试。

协议调试脚本

如果你在 GameSupport 源码仓库中开发，可以使用协议调试脚本启动一个受信任的本地插件包，观察完整握手、心跳、事件和停止流程。

./scripts/ipc-debug.ps1 -PluginDirectory ./build/javascript-example
调试脚本会直接执行指定 EXE

只对你自己的或已经审核过的本地开发包使用。不要把来历不明的插件目录传给调试脚本。

首次启动声明能力自动启用，启动后进入 running。
心跳连续运行 30 秒以上不被终止。
测试事件点击按钮后事件记录出现，绑定的音效或动画执行。
业务事件真实检测条件满足时发送事件，频率符合预期。
停止点击停止后 2 秒内退出，没有残留子进程。
配置保存配置会停止进程；重新启动后使用新配置。
更新同 ID、更高版本可更新；配置保留；声明能力自动启用。
完整性修改包内文件后，安装或启动被拒绝。
隔离插件崩溃、发送非法 JSON 或超过速率限制时，主程序继续运行。

常见调试手法

  • 临时把收到的消息类型打到 stderr：console.error(message.type, message.command ?? '')。不要打到 stdout。
  • 在关键分支记录自己的状态：初始化、授权、启动、定时器触发、停止。
  • 检查退出码。Host 会把异常退出记录为插件错误；反复重启说明进程在启动早期失败。
  • 确认事件 ID 完全一致，包括大小写、点和下划线。规则不会模糊匹配。
  • 确认 manifest 的 events 与代码中发送的 ID 一致，且已授权 events.emit。
  • 检查是否有同步长任务阻塞事件循环，导致无法回复 pong。
  • 停止时清理所有定时器、文件句柄、网络连接和子进程。
实践 / Distribution

分发与审核边界

当前版本提供本地开发安装通道。它不是面向任意第三方 EXE 的公开市场，也没有自动恶意软件扫描、证书信任库或审核签名链。

不要把它当作公开 EXE 市场

本地安装会校验 manifest 和哈希，但不会替你判断代码是否恶意。分发前请自行完成代码审查、依赖审查和签名策略。社区 Native 包默认不放行。

发布包应该包含

内容用途
manifest.json身份、事件、权限和完整性清单。
plugin.cjs插件逻辑。
bin/launcher.exeHost 启动入口。
bin/node.exe随包 Node 运行时。
NODE-LICENSE.txt运行时许可文本。
README.md功能、权限用途、数据访问、配置示例和卸载说明。
版本说明新增事件、修复内容、破坏性变化和新声明能力与配置兼容说明。

README 至少写清楚

  • 插件读取哪些数据、访问哪些目录、是否联网。
  • 每个权限为什么需要，尤其是 screen.capture 和 filesystem.read。
  • 发送哪些事件，事件 ID 和含义。
  • 配置字段、取值范围和默认值。
  • 如何停止、卸载，以及更新后自动启用声明能力。
  • 已知限制，例如独占全屏无法截图、只支持特定游戏版本。

内容市场与 Native 审核

GameSupport 的内容市场可以发布免费素材包，支持本机测试审核和已部署的服务端。Native 插件的边界更严格：

  • 上传只保存和校验包，不会执行上传的 EXE。
  • Native 包提交后保持待审核，不会仅凭页面按钮通过。
  • 审核通过还需要运营方把已完成独立安全与签名审核的整包 ZIP 哈希加入受信任清单，重启服务后才可批准。
  • 市场包不能覆盖应用内置插件。
  • 默认不放行任何社区 Native 包。

这些限制是审核策略，不是自动扫描服务。发布者仍需要自行保证代码、依赖和更新链路的安全。

实践 / Security

安全须知

插件以当前 Windows 用户身份运行。能力声明不是安全隔离，安装即启用声明能力，不是操作系统层面的隔离。写插件时要把这一点当作前提。

最小权限

只声明功能真正需要的权限。能读一个日志文件，就不要申请整个磁盘；能本地处理，就不要联网。

校验输入

配置、文件名、网络响应和游戏日志都可能包含意外内容。限制长度、类型和范围，不要直接拼命令或路径。

保护 stdout

只写协议 JSON。第三方库如果默认打印日志，把它重定向到 stderr，否则插件会被判定为协议错误。

清理资源

停止时清除定时器、关闭连接、释放句柄。不要启动脱离管理的长期子进程；Job Object 只回收进程树。

不要带密钥

插件包会被用户完整安装和校验。不要把 API 密钥、令牌或私有证书放进包里，也不要写进日志。

供应链安全

锁定依赖版本，审查 npm 包和二进制来源。分发前重新构建，避免把开发机上的临时文件带进包。

用户数据与隐私

  • 只采集功能必需的数据。采集屏幕画面时，明确说明是否落盘、保存多久、如何删除。
  • 日志可能包含用户目录、游戏状态或账号信息。默认不要上传，也不要写入插件包目录。
  • 联网功能要提供失败路径。网络不可用时，插件不应崩溃或无限重试。
  • 不要修改用户的游戏文件或系统配置，除非这是插件明确声明并被用户授权的功能。
权限声明的价值在于可审核

用户看到的不是你的代码，而是 manifest、README 和权限列表。把它们写清楚，比在代码里“尽量少做坏事”更能建立信任。

参考 / Troubleshooting

故障排查

按“安装 → 启动 → 心跳 → 事件 → 规则 → 播放”的顺序定位。先确认插件进程是否健康，再检查事件绑定，最后才怀疑音频或动画模块。

安装时提示清单无效或 Schema 校验失败

清单不允许未定义字段。逐项检查：manifest_version 是否为 1，ID 是否为至少三段的小写反向域名，版本是否符合 SemVer，runtime 是否符合 native 或 web 对应字段，权限是否在六种枚举内，事件 ID 是否只含小写字母、数字、下划线和点。

先用 manifest.schema.json 校验，再重新构建。不要手工修补安装目录里的清单，哈希会立即失效。

安装时提示文件哈希不匹配或缺少文件

常见原因是修改了 plugin.cjs 但没有重新构建，或者新增了文件却没有加入 files 哈希。删除旧的构建目录，重新运行 node build.mjs，再安装新目录。

如果哈希清单里包含 NODE-LICENSE.txt，确认它确实被复制到了包根目录。任何包内文件都在校验范围内。

启动后立即变成错误或停止

先看插件日志。常见原因：

  • 启动器找不到 bin/node.exe 或 plugin.cjs，包结构不完整。
  • hello 中的 plugin_id 或 version 与 manifest 不一致。
  • 进程在 5 秒内没有发出 hello，或 Node 语法错误导致启动失败。
  • stdout 输出了普通日志，Host 把第一行当成非法协议消息。

在构建目录直接运行 Node 做握手冒烟测试，能把“协议代码错误”和“安装包问题”分开。

运行几秒后被自动终止

这是心跳超时的典型表现。Host 每 5 秒发送 ping，15 秒内没有 pong 就会终止插件。检查是否有同步死循环、长时间 CPU 计算、同步文件读取或阻塞式网络请求占住了事件循环。

也可能是发送频率超过每秒 100 条消息，或队列满。把高频事件去重、合并或降到合理频率。

点击“请求测试事件”没有反应

  • 插件必须处于 running，测试按钮在停止状态下不可用。
  • 你的插件需要处理 configure 命令。模板用 emit_test 触发一次发送；如果你删掉了这段逻辑，测试按钮不会产生事件。
  • 检查 canEmit 是否为 true，也就是 initialize 的权限列表是否包含 events.emit。
  • 检查事件是否在 manifest 中声明，以及是否已经创建规则。

事件记录有内容，但没有声音或动画

  • 规则是否保存并启用，事件 ID 是否与插件发送的完全一致。
  • 规则里是否加入了音效或动画动作，延迟、冷却和次数上限是否合理。
  • 主程序是否处于暂停状态，音量为零，或输出设备不可用。
  • 事件记录中的“已调度”只表示进入队列；实际播放错误会写入日志。

修改代码后行为没有变化

Host 运行的是已安装目录中的副本，不是你源码目录里的文件。修改后必须重新构建、提升版本、停止旧插件、通过“更新包”安装新包，然后重新启动。

直接编辑用户插件目录会破坏完整性校验，不是支持的工作流。

更新失败或提示版本不够高

更新要求同 ID、版本严格更高、所有文件哈希正确，并且旧插件已经停止。最常见的原因是只改了 manifest 版本，忘了改 plugin.cjs 的 hello 版本，或者没有重新构建导致哈希还是旧的。

把两个版本号同时提升，重新构建，再选择新目录更新。

保存配置后插件停止了

这是预期行为。保存配置或权限会停止运行中的进程，让新设置在下次启动时通过 initialize 生效。重新点击启动即可。

事件因能力声明被拒绝

Host 自动启用 manifest 声明的能力，并检查事件是否在清单内；请确认 events.emit 和事件 ID 均已声明。

重新构建完整性清单后更新插件，再重启事件进程。配置页不再显示权限选项。

中文日志乱码或 JSON 解析失败

协议要求 UTF-8。用 JSON.stringify() 生成消息，不要手拼字符串。日志写 stderr，不要在 stdout 输出中文提示行。

读取外部文件时显式指定 UTF-8，避免把控制台编码或 BOM 带进协议消息。每条消息必须以 LF 结尾。

能不能直接安装一个 .js 文件

不能。Native 事件运行时的入口必须是包内的 .exe，且启动时不传参数。模板的 launcher.exe 就是为了把 Node 包进 Native 插件模型。

插件能不能自己播放音效或显示动画

工具页面可在自己的 Canvas 中预览动画，并通过 effects.save 导出到动画库。正式桌面播放由用户在触发中心规则中关联；事件插件继续提供事件。

需要开启本地 HTTP API 吗

不需要。插件走 stdin/stdout。本地 HTTP API 是给外部程序调用 Event Bus 的另一条通道，与插件协议无关。

支持 32 位、ARM 或 Linux 吗

当前只支持 Windows x64。manifest 的运行时声明固定为 os: ["windows"] 和 arch: ["x86_64"]。

参考 / Compatibility

兼容性与版本策略

插件、Host 和协议各有版本。它们不要求数字相同，但必须满足清单与协议声明的约束。

组件当前版本约束
GameSupport0.11.0+插件系统的宿主。本文档按 0.11.0+ 的实际行为编写。
Plugin SDK1.1兼容原事件插件，新增 ui.pages 与 web runtime；页面 API 1.0。
GS-IPC1.0hello 与 initialize 中的 protocol 必须是 gs-ipc/1.0。

版本规则

  • 插件版本使用 SemVer。更新必须同 ID 且严格更高；降级被拒绝。
  • 协议版本必须精确匹配。Host 当前只接受 gs-ipc/1.0。
  • 清单版本固定为 1。未来若变更格式，会通过新的 manifest_version 区分。
  • 事件 ID是兼容性契约。新增事件是安全变化；重命名或删除是破坏性变化。
  • 破坏性变化应提升插件主版本，并在 README 与版本说明中明确写出迁移方式。
  • 废弃事件建议至少保留一个次版本周期，先停止文档推荐，再在下个主版本移除。

当前实现边界

  • 只支持 Native EXE 入口，不支持 WASM 或直接以 JS 文件作为入口。
  • 没有公共 Native 插件市场，没有自动恶意软件扫描或证书信任库。
  • 没有审核签名链；Native 包默认不放行，需独立审核后加入受信任哈希清单。
  • 更新有常规失败回滚，但没有断电级跨文件系统事务恢复日志。
  • 权限是运行策略与审核记录，不能约束 EXE 的 Windows 权限。
不要假设未写入文档的行为

协议以本文档、仓库中的 Schema 和实际安装包行为为准。依赖未公开的字段、消息类型或文件布局，可能在后续版本失效。
